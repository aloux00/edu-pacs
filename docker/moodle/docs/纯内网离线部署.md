# EduPACS + Moodle 一键栈 · 纯内网离线部署

适用场景：教学机房 / 院内服务器**完全无互联网**，需要部署 Moodle + EduPACS + OHIF + LTI 1.3 + xAPI 一键集成栈。

核心原则：**内网机不拉取、不构建**。所有需要外网的步骤（拉镜像、pip 装依赖）都在有网机上提前完成，打成离线包拷入。

## 一、有网机制作离线包（一次性）

在能上网且装有 Docker 的机器上：

```bash
cd pkg5-src/docker/moodle
python scripts/build_offline.py          # 产出在 docker/moodle/deploy/EduPACS-Moodle离线包-<日期>/
# 可选参数：
#   --output D:/离线包      指定输出目录
#   --no-build             不重新构建 app 镜像（已有镜像时更快）
#   --skip-pull            不重新 pull（用本地缓存镜像）
```

脚本自动完成：构建 app 镜像（含 pip 依赖）→ 拉取 4 个外部镜像 → 复制源码（排除 .env/数据/虚拟环境）→ `docker save` 全部 5 个镜像为 `images.tar` → 生成 SHA-256 校验和与镜像清单 → 自检关键文件。

把整个 `EduPACS-Moodle离线包-<日期>/` 目录（或打成 zip）拷入内网机（U 盘/移动硬盘）。

**离线包内容**（约 6.5 GB）：

| 镜像 | 用途 | 解压后大小 |
|---|---|---|
| docker.io/library/mariadb:11.2 | Moodle 数据库 | 556 MB |
| docker.io/bitnamilegacy/moodle:4.5 | Moodle + 引导脚本 | 1.12 GB |
| orthancteam/orthanc:26.9.1 | DICOM 存储 / OHIF | 3.86 GB |
| python:3.12-slim | 内置 LRS 运行底座 | 179 MB |
| edupacs-moodle-app:1.0.0 | 教学系统（有网机预构建） | 384 MB |

## 二、内网机部署（三步）

### 前置：内网机需要 Docker

- **Windows**：Docker Desktop（Linux 容器模式）。安装器可在有网机下载后拷入。
- **Ubuntu**：内网 apt 源装 `docker.io docker-compose-v2`；或从有网机 `apt-get download` 拉全依赖链 deb 离线安装。
- 另需 Python 3.8+（仅宿主机跑 `configure.py`，标准库即可）。

### 第 1 步：导入镜像（只需一次）

- Windows：双击离线包根目录「一键导入镜像.bat」（自动校验 SHA-256 → `docker load`）。
- Linux：`bash load_images.sh`

### 第 2 步：配置内网地址

首次启动前，把 `edupacs/docker/moodle/.env.example` 复制为 `.env`，只改两行（端口不变）：

```ini
MOODLE_PUBLIC_HOST=172.16.21.132:8080     # 改成内网服务器 IP
EDUPACS_PUBLIC_HOST=172.16.21.132:8000
```

其余 `CHANGE_ME` 保持不动，启动脚本会自动生成随机密码。

### 第 3 步：启动

- Windows：双击离线包根目录「启动Moodle集成栈.bat」（内部设 `OFFLINE=1`）。
- Linux：`OFFLINE=1 bash edupacs/docker/moodle/start.sh`

离线模式自动跳过镜像拉取与构建，其余流程（配置生成 → 启动 → Moodle 引导建课注册 LTI → 回写 Deployment ID → 状态自检）与在线版完全一致。

启动完成后按输出提示访问 Moodle / EduPACS，教学使用方法见 `docs/Moodle一键集成说明.md`。

## 三、手工部署（不用离线脚本）

如果偏好手动操作，等价命令：

```bash
# 有网机：导出镜像（5 个缺一不可）
docker save -o images.tar \
  docker.io/library/mariadb:11.2 \
  docker.io/bitnamilegacy/moodle:4.5 \
  orthancteam/orthanc:26.9.1 \
  python:3.12-slim \
  edupacs-moodle-app:1.0.0

# 内网机：导入 + 配置 + 启动（不带 --build、不 pull）
docker load -i images.tar
cd pkg5-src/docker/moodle
cp .env.example .env    # 编辑两个 PUBLIC_HOST
docker compose -f docker-compose.moodle.yml up -d
docker compose -f docker-compose.moodle.yml --profile tools run --rm bootstrap
python scripts/configure.py --finalize
python scripts/configure.py --status
```

## 四、内网特有注意点

| 事项 | 说明 |
|---|---|
| 镜像名必须与 .env 一致 | `.env` 里 `MOODLE_IMAGE` / `MARIADB_IMAGE` 等写的就是 save 时的名字，改名后 load 进来也找不到 |
| app 镜像必须预构建 | Dockerfile 含 `pip install`，内网现场 build 必卡在拉依赖 |
| python:3.12-slim 别漏 | 它是 LRS 服务的镜像，不显眼但必需 |
| Moodle 中文语言包 | Bitnami 镜像内置 `zh_cn`，无需外网 |
| 升级 | 新版 app 镜像重新 save → 内网 `docker load` → `docker compose up -d`（不加 --build），数据在卷中不受影响 |
| 多台内网机 | 可在内网架一个 `registry:2`（本身也是离线导入的镜像），外网机 push 前缀化镜像名，内网统一 pull |

## 五、内网部署自检清单

```bash
# 1. 镜像齐全（5 个）
docker images | grep -E "mariadb|bitnamilegacy|orthancteam|python|edupacs"

# 2. 容器全部 Up（除按需的 bootstrap）
docker compose -f docker-compose.moodle.yml ps

# 3. 端点自检（应全 OK）
python scripts/configure.py --status

# 4. 浏览器验证
#    Moodle 登录 → 课程 → 「EduPACS 影像阅片」→ OIDC 跳转 → 病例列表 → OHIF 阅片
```

## 六、常见问题

| 现象 | 处理 |
|---|---|
| `pull access denied` / 网络超时 | 启动时没走离线模式：确认用离线包根目录的启动入口（OFFLINE=1），或手工启动不带 pull/--build |
| `manifest unknown` / 找不到镜像 | 镜像没导入或名字不一致：`docker images` 核对 5 个镜像与 `.env` 中名称一致 |
| Moodle 登录页 500 | 引导容器用户与 Web 不一致（root 污染）；在 moodle 容器执行 `find /bitnami/moodledata -user root -exec chown daemon:daemon {} +` |
| LTI 报 iss 不匹配 | `.env` 的 `MOODLE_PUBLIC_HOST` 与浏览器地址栏不完全一致；改后重跑一键启动 |
| 校验和不匹配 | 传输损坏，重新拷贝 images.tar |
| 端口被占 | 改 `.env` 的 `MOODLE_PORT` / `EDUPACS_PORT` / `DICOM_PORT` 及对应 PUBLIC_HOST |
