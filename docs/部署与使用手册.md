# EduPACS 教学病例库系统 — 部署与使用手册

> 基座：**Orthanc 1.13.0**（DICOM 存储 + DICOMweb）+ **OHIF Viewer**（官方 OrthancOHIF 插件内嵌）+ **FastAPI/SQLite 教学应用层**
> 规模：满足约 100 名师生并发的院内内网教学场景（SQLite 单机即可承载，后续如需可平滑升级 PostgreSQL/MySQL）

---

## 1. 系统架构

```
浏览器（师生，约100人）—— 只访问 8000 端口
   │  http://<服务器IP>:8000        教学病例库系统（登录/病例管理/问答/统计）
   │       ├── /ohif/* 、/dicom-web/*   FastAPI 反向代理 → 本机 Orthanc（自动附带认证）
   │       │     └── 内嵌 OHIF Viewer iframe：同源 /ohif/viewer?StudyInstanceUIDs=...
   │       └── REST API /api/*      FastAPI 应用层（SQLite 存账号/病例/答卷/记录）
   │
Orthanc（http 8042 仅本机可达 / DICOM 4242）
   ├── HTTP 认证已启用（服务账号见 orthanc.json RegisteredUsers，默认 edupacs_service）
   ├── DICOMweb（QIDO-RS / WADO-RS / STOW-RS）→ 供 OHIF 取图（经 8000 反代）
   ├── OrthancOHIF 插件 → 直接托管 OHIF 阅片前端
   └── storage/ 目录 → DICOM 影像文件 + SQLite 索引
```

各组件职责：

| 组件 | 端口 | 作用 |
|---|---|---|
| Orthanc | 8042 (HTTP，仅本机) / 4242 (DICOM) | 医学影像存储、DICOMweb 服务、托管 OHIF 阅片页；HTTP 已启用认证 |
| OHIF Viewer | 经 8000 反代访问 | 浏览器内专业阅片（窗宽窗位/缩放/测量/标注） |
| FastAPI 教学应用 | 8000 | 账号权限、病例管理、教学问答、学习记录、统计看板；并反向代理 OHIF/DICOMweb 到 Orthanc |
| SQLite | app/data/app.db | 应用层数据库（用户、病例元数据、答卷、学习记录） |

## 3. 快速启动（当前演示环境）

### 3.1 图形启动器（推荐，日常运维用这个）

**原生版（v4 起默认，赛博朋克 HUD 界面）**：`EduPACS启动器.bat` 现在优先启动原生 C 语言启动器 `EduPACS启动器.exe`（193KB 静态链接，无依赖，启动即开、检测在后台线程、界面不卡顿；深色 HUD 网格背景、霓虹状态灯、扫描线动画、悬停高亮按钮，窗口与任务栏图标为内嵌的 24/32/48/64/128/256 六尺寸应用图标）；找不到 exe 时自动回退到 PowerShell 版 `scripts\launcher.ps1`。功能一致：

1. 双击项目根目录的 **`EduPACS启动器.bat`**（或直接双击 `EduPACS启动器.exe`），弹出启动器窗口
2. 窗口内两个状态灯每 2 秒后台刷新显示服务状态：
   - `● Orthanc` — DICOM 4242 / HTTP 8042 / OHIF 阅片（含认证状态识别）
   - `● 教学系统` — HTTP 8000 / 账号·病例·问答·统计
3. 点 **「一键启动」**：自动拉起两个服务，就绪后自动打开浏览器进入系统
4. 点 **「一键停止」**：安全停止两个服务（学生/教师将暂时无法访问）
5. 另有「打开教学系统」「打开 Orthanc 后台」两个快捷按钮；窗口底部显示**本机与局域网访问地址**（可直接念给学生/教师）

> 说明：启动器只管理本项目目录下的进程，点「关闭」只关界面、**不会**停服务；要真正停服务请点「一键停止」。
>
> 原生版命令行模式（供运维脚本调用）：`EduPACS启动器.exe --status` / `--start` / `--stop`（退出码 0=就绪/成功）。注意：PowerShell 里用 `Start-Process -Wait` 调 `--start` 会因宿主等待后代服务进程而挂起，请改用 `& $exe --start` 后接 `--status` 轮询；`--status`/`--stop` 可放心 `-Wait`。

### 3.2 命令行方式（无界面，适合远程桌面/脚本调用）

1. 运行 `scripts\start_all.ps1`（右键 → 使用 PowerShell 运行）
2. 浏览器访问 `http://127.0.0.1:8000`
3. 停止用 `scripts\stop_all.ps1`（**安全停止**：只结束命令行可确认属于本项目的 Orthanc/python 进程，不会误杀同机其它项目的同名服务；发现 8000/8042 被他人进程占用时只报告、不动手）

### 3.3 登录账号
   - 管理员：`admin / admin123`
   - 演示教师：`teacher01 / teach123`
   - 演示学生：`st001 ~ st200`，密码 `stXXX@pass`（如 st001 → `st001@pass`）
4. 首次空库可导入演示数据：`.\venv\Scripts\python tools\import_cases.py`

## 4. 迁移到内网服务器（Windows）

### 4.1 环境要求
- Windows Server 2016+ / Windows 10+（64 位）；Linux 服务器（Ubuntu 20.04+）部署见 4.4 节
- Python 3.12+（仅应用层需要；Orthanc 为独立 exe 无需安装；3.10/3.11 不满足 `tarfile` 安全过滤要求）
- 开放端口：8000（教学系统与阅片入口，师生仅需此端口）、4242（DICOM，影像设备推送用，可按需开放）；**8042 仅服务器本机可达**（HTTP 已启用认证，师生经 8000 反代访问阅片器，无需对内网开放）

### 4.2 部署步骤（推荐用一键安装器）
1. 整包拷贝 `edu-pacs/` 目录到服务器（如 `D:\edu-pacs`）
2. 在项目根目录运行安装器（自动检测 Python → 建 `.venv` → 安装锁定版本依赖；幂等可重复执行）：
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\install.ps1
   ```
   可选开关：`-WithFirewall`（放行 8000/4242 入站，需管理员）、`-WithShortcuts`（创建桌面快捷方式）、
   `-WithAutostart`（注册开机自启计划任务，不弹浏览器）、`-IndexUrl <镜像源>`、`-Wheels <目录>`。部署包已内置 `wheels\`（Windows 64 位 / Python 3.12），安装器检测到后**默认完全离线安装**，无需联网或传参。
   > 手工等价步骤：`python -m venv .venv` → `.venv\Scripts\pip install -r requirements.lock.txt -i https://mirrors.aliyun.com/pypi/simple`
3. 在项目根目录双击 `EduPACS启动器.bat` → 点「一键启动」（或运行 `scripts\start_all.ps1`）
4. 首次运行自动创建默认管理员 `admin / admin123`，**首次登录强制修改密码**（弹窗不可跳过）
5. 教师上传病例 → 发布 → 学生学习（见第 9 节教学流程）
6. 交付/升级前后可运行端到端冒烟测试（32 项断言：脱敏零泄漏/盲读解锁/批阅/统计/权限隔离/**阅片代理写保护**）：
   ```powershell
   .venv\Scripts\python tools\smoke_test.py --orthanc-user edupacs_service --orthanc-pass <服务账号密码，见 orthanc\orthanc.json>
   ```

### 4.3 开机自启 / 后台常驻（可选）

> **两种方案二选一，不要同时启用**：同时开会出现两个进程抢 8000/8042 端口。

#### 方式 A（服务器推荐）：注册为真正的 Windows 服务

适合部署在内网服务器、要求"开机自动后台运行、无人登录桌面也能用、崩溃自动重启"的场景。
部署包已内置 WinSW（services 目录，无需联网下载），把 Orthanc 与教学后端注册为两个服务：

1. 完成 4.2 安装（`.venv` 必须存在）
2. 在项目根目录**右键 `安装为Windows服务.bat` → 以管理员身份运行**（bat 也会自动请求提权）
   - 脚本自动：管理员校验 → 文件完整性检查 → 端口冲突检查 → 禁用旧的 `EduPACS-Autostart` 计划任务 → 安装两个服务 → 启动 → 8042/8000 健康检查；任一步失败都会打印诊断并写入 `install-service.log`，出错不会闪退
   - 幂等：重复运行会先卸载旧服务再重装
   - 加 `-NoStart` 参数可只注册不启动（重启后自动起）
3. 日常管理（均无需登录桌面）：
   - 图形：`services.msc`，服务名 `EduPACS Orthanc 影像服务` / `EduPACS 教学系统后端`
   - 命令行：`net start|stop EduPACS-Orthanc`、`net start|stop EduPACS-App`
   - 一键查看状态：双击 `查看服务状态.bat`（或 `scripts\service-status.ps1 -Action Start|Stop|Restart`）
   - 服务控制台日志：`logs\EduPACS-Orthanc.*.log`、`logs\EduPACS-App.*.log`（按大小滚动）
4. 卸载：`右键 卸载Windows服务.bat → 以管理员身份运行`。**只删服务注册，数据库/影像/备份/日志全部保留**；卸载后如需回到计划任务方式：`Enable-ScheduledTask -TaskName EduPACS-Autostart`

关键配置（在 `services\*.xml`，改后需重新安装服务生效）：
- `EduPACS-Orthanc.xml`：可执行 `orthanc\Orthanc.exe`，工作目录必须是 `orthanc\`（`orthanc.json` 中 storage/plugins 为相对路径）
- `EduPACS-App.xml`：可执行 `.venv\Scripts\python.exe -m uvicorn app.backend.main:app --host 0.0.0.0 --port 8000`，工作目录为项目根（`main.py` 以自身位置推导 `ROOT`）
- `<depend>EduPACS-Orthanc</depend>`：保证开机先起 Orthanc 再起后端
- `<onfailure action="restart" delay="10 sec"/>`：崩溃后 10 秒自动重启
- 路径全部用 `%BASE%`（XML 所在目录）相对表示，整包搬到任意盘符都可读

> 服务模式下不需要启动器常驻托盘；启动器仅作手动管理/打开浏览器用。

#### 方式 B（免装工具）：开机自启计划任务

安装时加 `-WithAutostart`，注册计划任务 `EduPACS-Autostart`，开机执行 `scripts\start_all.ps1 -NoBrowser`。
注意：该方式依赖登录会话，且**没有崩溃自动重启**；服务器长期运行优先用方式 A。

### 4.4 Linux（Ubuntu）服务器部署

> 以 **Ubuntu 24.04 LTS** 原生 apt 方案为例（不依赖 Docker）。Ubuntu 22.04 步骤相同，但 apt 里可能没有 `orthanc-ohif` 插件包，需先 `apt policy orthanc-ohif` 确认，没有则改用 24.04 或独立部署 OHIF；各包版本以实际查询为准（本系统针对 Orthanc 1.13 开发并实测，旧版本 API 行为可能有差异，部署后务必跑第 6 步冒烟验证）。

**① 安装 Orthanc 与插件（系统源自带，无需编译）**

```bash
sudo apt update
sudo apt install -y orthanc orthanc-dicomweb orthanc-ohif
```

Debian 系打包会把插件配置放在 `/etc/orthanc/` 下并随主服务加载；若插件未自动生效，把对应配置并入 `/etc/orthanc/orthanc.json` 的 `Plugins` 字段后重启服务。

**② 修改 `/etc/orthanc/orthanc.json` 关键安全项（对齐第 10 节）**

```json
"AuthenticationEnabled": true,
"RemoteAccessAllowed": false,
"RegisteredUsers": { "edupacs_service": "改成强密码" },
"DicomPort": 4242,
"HttpPort": 8042
```

数据目录默认在 `/var/lib/orthanc/`（index 数据库与 storage 影像），确认所在分区容量充足后：`sudo systemctl restart orthanc`。验证：`curl -u edupacs_service:密码 http://127.0.0.1:8042/system` 应返回 200；不带认证应返回 401。

**③ 部署教学系统**

```bash
sudo mkdir -p /opt/edu-pacs && cd /opt/edu-pacs
# 上传源码（git clone 或解包，不含 orthanc/ 目录——Linux 用系统包的 Orthanc）
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple
sudo chown -R edu-pacs:edu-pacs /opt/edu-pacs   # 建议建专用账号并仅授 app/data 与 .temp 写权限
```

**④ systemd 服务 `/etc/systemd/system/edu-pacs.service`**

```ini
[Unit]
Description=EduPACS Teaching Case Library
After=network.target orthanc.service

[Service]
Type=simple
User=edu-pacs
WorkingDirectory=/opt/edu-pacs
Environment=ORTHANC_URL=http://127.0.0.1:8042
Environment=ORTHANC_AUTH_USER=edupacs_service
Environment=ORTHANC_AUTH_PASS=与 orthanc.json 一致
ExecStart=/opt/edu-pacs/.venv/bin/python -m uvicorn app.backend.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> **重要**：Linux 下 Orthanc 配置在 `/etc/orthanc/`，应用层读不到项目内 `orthanc/orthanc.json`，**必须**用 `ORTHANC_AUTH_USER/PASS` 环境变量传服务账号（代码已支持）；`ORTHANC_URL` 亦已支持。

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now edu-pacs
journalctl -u edu-pacs -f        # 看日志
```

**⑤ 防火墙**

```bash
sudo ufw allow 8000/tcp          # 教学系统与阅片（师生唯一入口）
sudo ufw allow 4242/tcp          # DICOM 设备直推（按需）
# 8042 不要开放：仅本机可达，师生经 8000 反代访问阅片
```

**⑥ 部署后验证（必做）**

```bash
.venv/bin/python tools/smoke_test.py --orthanc-user edupacs_service --orthanc-pass '服务账号密码'
```

32 项全部通过即可交付（含脱敏零泄漏、反代写保护、权限隔离）。

**⑦ 数据迁移（Windows → Ubuntu）**

1. 两侧都停服务；打包 Windows 机的 `orthanc\storage\` 与 `app\data\`
2. Orthanc 侧：把 storage 内容放到 Ubuntu 的 Orthanc 数据目录（注意 Ubuntu 打包把 index 与影像的路径拆分为 `/var/lib/orthanc/` 下不同子目录，需对照 `/etc/orthanc/orthanc.json` 的 `StorageDirectory`/`DatabaseDirectory` 放置）；Orthanc 索引库跨平台、自动升级 schema
3. 应用侧：`app/data/app.db` 原样放到 `/opt/edu-pacs/app/data/`（SQLite 跨平台）；**secret.key 不要拷贝**，首次启动自动生成（旧 token 全部失效，重新登录即可）
4. 先启 Orthanc → 再启教学系统 → 跑第 ⑥ 步冒烟 → 浏览器抽查一个病例的 OHIF 阅片

**⑧ 日常运维**

- 备份：cron 每日打包 `/var/lib/orthanc/` 与 `/opt/edu-pacs/app/data/`（app.db 建议用 `sqlite3 app.db ".backup ..."` 热备）
- 升级：`git pull` → `pip install -r requirements.txt` → `systemctl restart edu-pacs`
- 如需 HTTPS/公网：前置 nginx 反代 8000 并加 TLS，后端不动

### 4.5 Docker 部署（Ubuntu Server，镜像化双轨方案）

> 与 4.4 的关系：**两条 Linux 部署路线并存**。4.4 原生 apt 方案适合「不装 Docker 的服务器」；
> 4.5 Docker 方案适合「追求环境一致、快速复制到多台服务器」的场景，交付物是**离线镜像包**
> （内网无外网也能部署）。Windows zip 包与 Docker 包为双轨并存，应用代码与数据结构完全一致，可互相迁移。

**① 离线镜像包制作（在有外网、装有 Docker 的 Linux 机器上执行一次）**

```bash
bash docker/build-offline-images.sh
# 产物：deploy/EduPACS-Docker离线镜像包-<日期>.tar.gz（两个镜像 + compose + 配置 + 部署脚本）
# 可用环境变量覆盖：ORTHANC_IMAGE / APP_IMAGE / PIP_INDEX（默认清华源）
```

镜像构成：`orthancteam/orthanc:26.9.1`（官方镜像，内置 DicomWeb / OHIF / Explorer2 插件，配置节出现即自动启用，与 Windows 版插件组合对齐）+ `edupacs-app:1.0.0`（FastAPI 后端 + 纯静态前端，依赖按 requirements.lock.txt 全量锁定）。

**② 内网部署（Ubuntu Server 24.04 LTS，需已安装 docker + compose 插件）**

```bash
tar xzf EduPACS-Docker离线镜像包-*.tar.gz -C edupacs-docker && cd edupacs-docker
sudo bash deploy-offline.sh        # 一条命令完成
```

脚本自动：导入镜像 → 生成随机 Orthanc 服务账号密码写入 `.env`（权限 600）→ `docker compose up -d` → 等待就绪 → 打印访问地址与冒烟测试命令。幂等可重复执行。

**③ 安全模型（与 Windows 原生版对齐）**

| 项 | Docker 方案 | Windows 原生方案 |
|---|---|---|
| 师生入口 | 仅 8000（app 容器） | 仅 8000 |
| Orthanc 8042 | 不发布端口，仅 compose 内部网络，跨容器访问仍需 Basic 认证 | `RemoteAccessAllowed=false`，仅本机回环 + 认证 |
| DICOM 4242 | 按需发布（设备直推） | 按需开放防火墙 |
| 凭据 | `.env` 单点维护（600 权限） | `orthanc\orthanc.json` |
| 数据 | volume `edupacs_orthanc-storage` / `edupacs_app-data` | `orthanc\storage\` / `app\data\` |

> 注意：容器网络里 app 对 orthanc 是「远程」访问，故 `docker/orthanc-docker.json` 中 `RemoteAccessAllowed` 必须为 `true`；安全边界由「宿主机不发布 8042 端口 + 认证」承担，效果等价。

**④ 部署后必做：冒烟测试（32 项）**

```bash
U=$(grep ^EDUPACS_ORTHANC_USER= .env | cut -d= -f2-)
P=$(grep ^EDUPACS_ORTHANC_PASS= .env | cut -d= -f2-)
docker compose exec app python tools/smoke_test.py \
  --base http://127.0.0.1:8000 --orthanc http://orthanc:8042 \
  --orthanc-user "$U" --orthanc-pass "$P"
```

**⑤ 数据迁移（Windows ↔ Docker）**

1. Windows 侧停服务；打包 `orthanc\storage\`（去掉 `-wal/-shm`）与 `app\data\app.db`（secret.key 不拷贝）
2. 拷入服务器后：`docker compose stop`
3. 导入 volume：`docker run --rm -v edupacs_orthanc-storage:/d -v $PWD:/b alpine sh -c "cp -r /b/storage/. /d/"`
   与 `docker run --rm -v edupacs_app-data:/a -v $PWD:/b alpine sh -c "cp /b/app.db /a/"`
4. `docker compose up -d` → 跑 ④ 冒烟 → 浏览器抽查阅片

**⑥ 日常运维**

- 状态/日志：`docker compose ps` / `docker compose logs -f app`
- 备份（cron）：`docker run --rm -v edupacs_orthanc-storage:/d -v edupacs_app-data:/a -v $PWD:/b alpine tar czf /b/edupacs-backup-$(date +%F).tgz /d /a`
- 升级：新离线包 `docker load` → `.env` 不动 → `docker compose up -d`（volume 自动沿用）
- 改服务账号密码：改 `.env` → `docker compose up -d`（两个容器按新凭据重建）
- 防火墙：`ufw allow 8000/tcp && ufw allow 4242/tcp`

更多排错与细节见离线包内 `README-Docker部署说明.md`（源文件为 `docker/README-docker.md`）。

|---|---|

## 6. 字典管理（系统 / 模态 / 难度 / 疾病名称）

教师/管理员菜单「字典管理」维护四个类别的选项字典，供上传、编辑、筛选与统计使用：

- 四个页签独立维护，每项支持**新增 / 编辑 / 排序 / 停用 / 删除**
- **停用**：不再出现在下拉中，但历史病例不受影响；**删除**：仅允许未被病例引用的项
- 字典存在 `app\data\app.db`（dict_items 表），随每日备份自动覆盖

### 6.1 xlsx 模板样式与导入

点「下载 xlsx 模板」得到模板（含示例行与“填写说明”页），结构如下：

| 类别 | 代码 | 名称 | 排序 | 是否启用 |
|---|---|---|---|---|
| 系统 | | 呼吸系统 | 1 | 是 |
| 模态 | CT | CT | 1 | 是 |
| 难度 | 1 | 基础 | 1 | 是 |
| 疾病名称 | | 肺结节 | 1 | 是 |

规则：
- 类别只能填：系统 / 模态 / 难度 / 疾病名称（也接受英文 system/modality/difficulty/disease）
- 名称必填，同类别不能重复；**同名同类别自动跳过（不覆盖）**
- 代码：模态填标准缩写（CT/MR/DR/US/OT）；**难度必须填 1/2/3**，否则该行报错不入库
- 排序：数字越小越靠前；启用：填“是/停用”，留空默认启用
- 「导出当前字典」可随时备份全部字典为 xlsx

> **在受限浏览器（嵌入式 webview / 部分客户端内置浏览器）中**：
> - 若点「下载 xlsx 模板 / 导出当前字典」没有文件落地、点「导入 xlsx」不弹文件选择框，说明该环境屏蔽了浏览器的下载与文件选择能力
> - 请改用**「粘贴导入」**按钮：弹窗中每行粘贴一条 `类别,代码,名称,排序,是否启用`（逗号分隔，后两列可省略），例如 `系统,,骨关节系统,16`、`疾病名称,,骨软骨瘤`，无需任何文件操作即可导入
> - 下载也可直接在地址栏打开（用登录后页面的 token）：`http://服务器:8000/api/dicts/template?token=<token>`

## 7. 远程 PACS / 设备节点管理

教师/管理员菜单「远程节点」：

- **本机接收端**：AET `EDUPACS`、DICOM 端口 `4242` —— 影像设备直推的目标
- **DICOM 节点（Modalities）**：登记院内 PACS / 影像设备；新增保存后**即时生效（无需重启 Orthanc）**，并同步写入 `orthanc\orthanc.json`，重启后仍然有效；每行可 C-ECHO 测试连通
- **Orthanc 节点（Peers）**：HTTP 对接方式（院内平台互联），支持测试连通
- **远程查询（C-FIND）**：选节点 + 按患者ID/姓名/日期过滤 → 展示远程 studies → 点「拉取并导入」后自动 C-MOVE 拉回、**走统一脱敏管线**、入库为教学病例
- **本地未入库检查**：设备直推 4242 / 迁移合并的未登记数据出现在此，点「导入为病例」自动脱敏重建入库

安全要点：拉取与导入都会脱敏重建（原始 PHI 仅进教师可见的溯源表）；已入库检查会被拦截防止重复导入；远程 C-MOVE 需对方 PACS 允许本机 AET（EDUPACS）作为 MoveDestination。

## 8. 病例脱敏与检索设计（重要）

### 8.1 上传即脱敏（自动）

教师通过「上传病例」页上传 DICOM 时，系统在入库 Orthanc 之前自动完成脱敏：

| 处理项 | 规则 |
|---|---|
| 患者姓名 / 患者编号 / 检查号 / StudyID | 统一替换为教学编号（如 `EDU26-0007`） |
| 出生日期、住址、电话、民族、过敏史、其他患者ID/姓名 | 删除 |
| 医疗机构名称/地址、申请/执行/阅片医师、技师、设备序列号 | 删除或替换 |
| 私有标签（院内系统藏 PHI 的常见位置） | 全部删除（含序列内嵌套） |
| StudyInstanceUID / SeriesInstanceUID / SOPInstanceUID | 统一重写（防止与院内 PACS 交叉比对，同批文件映射一致） |
| 模态、部位、层厚、序列描述等诊断学字段 | 原样保留（教学需要） |

脱敏后 OHIF 阅片器显示的患者信息即为教学编号，学生端全链路看不到任何真实患者信息。

### 8.2 脱敏后如何检索？

检索体系从「患者身份」切换为「教学元数据」，病例库首页即支持：

- **教学编号 / 标题 / 病名 / 标签** 关键词搜索
- 科室、解剖系统、模态、难度多条件筛选
- 教师额外可用**原始住院号/原检查号反查**（溯源检索，学生无效）

### 8.3 溯源（受控）

原始患者编号/姓名/出生日期/原检查号/原 Study UID/原医疗机构存入独立溯源表：
- 仅 **教师/管理员** 可在病例详情页点「溯源信息」查看；学生访问接口直接 403
- 用途：教学更新、回院核对原始检查；溯源表与病例同备份（`app\data\app.db`）

### 8.4 盲读模式（防锚定依赖）

为避免学生先看老师结论再「对答案」，病例默认开启**盲读模式**：
- 学生进入病例时，**教学要点、参考诊断、各题参考答案均隐藏**，显示 🔒 提示
- 完成**全部题目作答**后自动解锁（无题目的病例则以打开阅片器为准）
- 提交后不要求等教师批阅即可见参考内容（及时反馈），得分/评语仍待批阅后显示
- 教师可在「编辑信息」中按病例关闭盲读（如正常对照病例）

### 8.5 患者匿名化临床信息（年龄/性别/病史等）

由于 DICOM 脱敏会清除 `PatientAge`、身份与联系方式等标签，教学所需的临床背景改由教师在**上传/导入/编辑**病例时手工填写，单独存入 SQLite 病例表，**不写回 DICOM**：

- 字段：**年龄、性别、主诉、病史、其他临床资料**（检验结果、检查目的、过敏史等）
- 位置：上传病例页 / 导入元信息弹窗 / 病例详情「编辑信息」→「患者匿名化信息」
- 学生端：病例详情页单独展示「患者匿名化信息」卡片；病例列表显示性别·年龄徽标；这些信息不受盲读模式锁定
- 检索：病例库搜索框可直接按年龄、性别、病史关键词检索
- 填写红线：**严禁**填写姓名、住院号、身份证号、电话、住址、具体日期等可识别信息；仅写教学必需的匿名化描述
- 旧库兼容：服务启动时自动为旧版 `app.db` 增加上述 5 列，历史病例显示为空，可在编辑页补填

## 9. 教学流程

1. **教师**：登录 → 上传病例（自动脱敏；填科室/系统/病名/难度、患者匿名化信息（年龄/性别/病史等）、教学要点/参考诊断，默认盲读模式）→ 发布
2. **教师**：病例详情页 → 添加问答题目（含参考答案与分值）
3. **学生**：登录 → 病例库 → 进入病例（盲读模式：教学要点/参考诊断暂不可见）→ 打开 OHIF 阅片器阅片（自动打卡）→ 书写笔记 → 作答全部题目
4. **作答完成**：学生端自动解锁教学要点、参考诊断与各题参考答案（及时自查）；得分/评语待教师批阅后显示
5. **教师**：病例详情页批阅答卷（打分+评语）；点「溯源信息」可查原始患者信息（学生不可见）
6. **教师/管理员**：看板与学情统计 → 掌握全员进度与成绩

## 10. 安全与运维建议

- **改默认密码**：新部署首次登录 admin 强制改密（弹窗不可跳过；部署包内 admin/teacher 等特权账号同样标记首登强制改密，学生演示账号不强制）；批量导入学生时密码列留空则**自动生成随机密码**（导入结果中一次性展示，请导出发放）；自助改密入口：登录后右上角头像 → 修改密码（POST /api/auth/change-password）
- **账号批量管理（管理员）**：用户管理页支持三种批量导入：**CSV 粘贴文本**、**xlsx 文件**（点「下载 xlsx 模板」按模板填写；受限浏览器用原生导航下载）、「填入 100 人示例」；用户名重复自动跳过。用户列表支持**勾选批量删除**（可全选；学习记录与答卷一并清理且不可恢复；不能删除自己，且系统始终保留至少一名管理员）。接口：POST `/api/users/import`、`/api/users/import-xlsx`、`/api/users/batch-delete`、GET `/api/users/template`
- **token 撤销**：token 内嵌密码哈希指纹，**改密后全员旧 token 立即失效**；停用账号即时生效（每次请求查库）
- **内网隔离**：8000/8042 仅对校园/院内网段开放；如需公网访问，务必加反向代理 + HTTPS + 额外认证
- **Orthanc HTTP 认证（已默认启用）**：orthanc.json 中 `AuthenticationEnabled=true`、`RemoteAccessAllowed=false`（8042 仅本机可达），仅保留一个服务账号（`RegisteredUsers`，默认 edupacs_service，密码见该文件）；师生与 OHIF 的所有请求由教学系统 8000 端口反向代理并自动附带认证，浏览器无需感知；DICOM 4242 走 DICOM 协议，设备直推/C-MOVE 不受影响。启动脚本（start_all.ps1 / launcher.ps1）与冒烟测试均可自动/参数化读取该账号；**修改服务账号后需重启 Orthanc**。运维上建议 8042 不在防火墙对内网开放（仅 127.0.0.1），外人无法直连阅片或浏览影像
- **阅片代理只读（反代写保护）**：8000 上的 `/ohif/*`、`/dicom-web/*` 仅放行 **GET/HEAD 只读请求**（QIDO/WADO 阅片所需），dicom-web 仅允许 studies/series/instances 子路径；POST/PUT/DELETE 一律 405 —— 防止未登录客户端借服务账号凭据向 Orthanc 写入/删除（STOW-RS 等）；影像写入只由教学系统上传通道在服务端执行
- **脱敏通道**：网页上传入库即脱敏；设备直推/远程拉取/本地导入均在导入时自动脱敏重建，详见第 8 节
- **脱敏范围**：除身份字段替换与 PHI 标签删除外，**描述类自由文本（StudyDescription/SeriesDescription/ProtocolName 等）中的已知患者姓名/住院号/生日字符串也会被替换为教学编号**；患者年龄默认清除；性别与检查日期默认保留（教学需要，可在 `app\backend\main.py` 顶部 `DEID_CLEAR_AGE / DEID_KEEP_SEX / DEID_KEEP_STUDY_DATE` 开关调整）
- **burned-in 文字（像素内烧录的 PHI）**：自动脱敏无法触及像素内文字。图片病例（论文/网络截图）上传时**必须勾选“确认图像内无患者可识别信息”**，请在收集素材时先行遮蔽；DICOM 设备图（DR/超声常见角标烧录）同理，教学库录入前请人工审查
- **备份（内置加密备份系统）**：管理员登录后「备份恢复」页面或命令行 `tools\backup.py` 一键创建 **AES-256-GCM 加密归档**（.edubak）——内容含 app.db、secret.key、orthanc.json（远程节点/服务账号）、Orthanc 索引与全部影像；备份期间自动优雅停止并重启本项目 Orthanc（数秒~数十秒一致性窗口，官方推荐做法；无法编排进程的部署自动降级热备份+WAL 重放）。支持**同机/异机目的地**（异机填 UNC/NFS 挂载路径；每次备份写入一个目的地，同机+异机两份需分别执行）、按目的地保留策略自动清理、归档校验（GCM+分区哈希）、恢复向导（干跑分析→沙箱→正式，覆盖前自动把现有数据移入回滚保障目录）。详见 10.1 节
- **磁盘**：Orthanc 默认不限制存储，建议在 orthanc.json 中按需设置 `MaximumStorageSize` 或定期归档
- **日志**：Orthanc 控制台窗口即日志；应用层可用 `--log-config` 或重定向输出到文件

### 10.1 备份与恢复（管理员操作手册）

**概念**：备份归档 `.edubak` = 明文头（时间/主机/备注/计数，纳入 GCM 认证域）+ AES-256-GCM 流式加密的 tar.gz（manifest + app.db + secret.key + orthanc.json + Orthanc 索引 + 全部影像文件）。密码经 PBKDF2-SHA256 600,000 轮派生 256 位密钥；GCM 自带防篡改。**密码丢失 = 数据不可恢复**（无后门），请按科室密钥管理制度单独保管。

**入口一：网页（管理员 → 备份恢复）**

1. 「立即备份」选目的地、输入备份密码（≥8 位）、备注 → 点开始 → 进度条实时显示（快照/一致性窗口/拷贝/打包/加密/写后校验）
2. 「归档列表」：列出各目的地归档（大小/时间/内容计数/备注）；行内「校验」输入密码做全量校验（GCM tag + 分区哈希）、「恢复…」打开恢复向导
3. 恢复向导：① 干跑分析（展示将恢复哪些分区、实例数、备份模式，不写入）→ ② 提示停服 → ③ 正式恢复需在服务器命令行执行（防网页误触）
4. 「备份目的地配置」：编辑/新增目的地（id/名称/路径/保留份数/启用），异机备份把路径改成 UNC（`\\FILESERVER\EduPACS备份`）或 NFS 挂载点

**入口二：命令行（计划任务/脚本用）**

```powershell
# 交互输密码
.venv\Scripts\python tools\backup.py backup --dest local
# 密码走受保护文件（避免命令行泄漏）
.venv\Scripts\python tools\backup.py backup --dest local --password-file D:\edu-pacs\.secure\bkpass.txt
.venv\Scripts\python tools\backup.py list --dest local          # 列归档
.venv\Scripts\python tools\backup.py verify backups\<归档> --password <密码>
.venv\Scripts\python tools\backup.py restore backups\<归档> --password <密码>          # 干跑分析
.venv\Scripts\python tools\backup.py restore backups\<归档> --password <密码> --apply   # 正式恢复（须先停服务）
.venv\Scripts\python tools\backup.py prune --dest local --keep 7
```

  /TR "D:\edu-pacs\.venv\Scripts\python.exe D:\edu-pacs\tools\backup.py backup --dest local --password-file D:\edu-pacs\.secure\bkpass.txt"

**恢复流程（灾难恢复演练步骤）**

1. 停服务：`EduPACS启动器.exe --stop` 或 `scripts\stop_all.ps1`（Ubuntu/Docker：`systemctl stop edu-pacs` / `docker compose down`）
2. 干跑确认：`restore <归档> --password ...`（输出将恢复的分区与实例数）
3. 正式恢复：加 `--apply`（会自动把现有 app/data、orthanc/storage、orthanc.json 移入 `.temp\pre-restore-<时间>\` 作为回滚保障）
4. 起服务 → 跑 `tools\smoke_test.py`（32 项全过再交付）→ 浏览器抽查一个病例的 OHIF 阅片
5. 异机恢复：在新服务器装好部署包（含 Python 依赖）后，把 `.edubak` 拷过去执行同样的 restore --apply

**安全要点**

- 备份密码与登录密码体系**相互独立**；归档内含 secret.key，拿到归档+密码即等于拿到全部教学数据，归档保管与传输必须按敏感数据管理
- 网页/API 的备份管理仅 **admin** 角色可用（教师/学生 403）；密码经 POST body 传输，务必在 HTTPS 或内网可信环境下使用
- 写后自动校验：备份完成即解密回读验证（GCM tag+分区哈希），失败归档自动丢弃，不会留下“假成功”备份

## 11. 常见问题

| 现象 | 处理 |
|---|---|
| 阅片器白屏 | 确认 Orthanc 已启动（服务器本机可用服务账号访问 http://127.0.0.1:8042/system 自检）；再确认教学系统 8000 可访问；浏览器需现代版本（Chrome/Edge） |
| 学生看不到病例 | 病例仍为草稿，教师详情页点「发布病例」 |
| 学生看不到教学要点/参考诊断 | 盲读模式：完成本病例全部题目作答后自动解锁；教师可在编辑信息里关闭盲读 |
| 病例没有年龄/性别/病史 | 在上传/导入或详情页「编辑信息」→「患者匿名化信息」中补填；旧库首次启动会自动补列，历史数据不会丢失 |
| 按真实患者姓名/住院号找不到病例 | 上传已自动脱敏，请用教学编号/标题/病名/标签/科室等检索；教师可用原始住院号反查（溯源检索） |
| 上传报 Orthanc 未接收 | 先确认 Orthanc 已启动；检查文件确为 DICOM（.dcm）；若报"无法解析"则文件非标准 DICOM |
| 其他电脑打不开 127.0.0.1 | 用服务器实际 IP 访问，如 http://192.168.x.x:8000 |
| Moodle 里点 EduPACS 后回到登录页 | 检查 `config/lti.json` 的 `public_url` / `iss` / Client ID / Deployment ID；浏览器是否拦截 Cookie；看 `app/data/integrations.log` |
| xAPI 语句没到 LRS | `GET /api/xapi/queue` 看 `last_error`；确认 LRS 认证走 `EDUPACS_XAPI_AUTH_HEADER`；未启用时队列为空属正常 |
| 端口被占用 | 修改 orthanc.json 的 HttpPort/DicomPort，以及 uvicorn --port，同步改 start_all.ps1；stop_all.ps1 遇到他人进程占用 8000/8042 时只报告不会误杀，改端口后请同步修改 stop_all.ps1 中的端口列表 |
| 想通过 8000 的 /dicom-web 上传/删除影像 | 设计上禁止：阅片代理仅 GET/HEAD（写操作 405），写入请走教学系统「上传病例」/「远程节点」通道（服务端自动附带认证与脱敏） |
| 双击 bat 没反应 / 窗口一闪就没 | 用命令行执行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\launcher.ps1 -TestAction Status` 看输出，并查看 `.temp\launcher_error.log` |
| 启动器按钮无反应或报错 | v2 已修复根因（浏览器查找改用硬编码路径 + 环境变量双保险，兼容缺失 `ProgramFiles(x86)` 的精简系统）；每次点击都会记录到 `.temp\launcher_click.log`，报错记录到 `.temp\launcher_error.log`，据此可精确定位 |
| 提示「你要如何打开此文件」选择框 | 系统未设默认浏览器。启动器优先调用 Edge，其次 Chrome；两者都未安装时请手动打开 http://127.0.0.1:8000 |
| PowerShell 脚本里中文乱码 | 脚本必须存为 **UTF-8 带 BOM**；用记事本「另存为」选 UTF-8（带 BOM），或改用 `EduPACS启动器.bat` |
| 执行 ps1 提示「禁止运行脚本」 | 用 bat 启动器（已带 `-ExecutionPolicy Bypass`），或执行 `Set-ExecutionPolicy -Scope Process Bypass` |
| 忘记 admin 密码 | 停止服务后删除 `app\data\app.db` 中 admin 行会重建默认密码（或用另一管理员重置） |
| 看不到「字典管理」「远程节点」等新菜单 | 浏览器缓存了旧版前端：按 **Ctrl+F5**（Mac：⌘⇧R）强制刷新即可；系统已对前端文件启用 no-cache 缓存策略，升级后不会再出现此问题 |
| 在 Orthanc Explorer 2（http://服务器:8042）里找不到远程节点维护入口 | Orthanc Explorer 2 的「设置」里只有系统信息与指标，**官方 UI 本身不提供节点维护界面**（传统 UI 也只有对已配置节点的查询/发送下拉）。请使用教学系统（8000）顶栏「**远程节点**」页维护：保存后即时生效并同步写入 orthanc.json |
| 打开 Orthanc 后台（8042）弹出浏览器认证框 | **正常现象**：8042 已启用 HTTP 认证。输入 orthanc.json `RegisteredUsers` 中的服务账号（默认 edupacs_service，密码见该文件）；教学系统（8000）本身不受影响，师生无需输入 |
| 改了 orthanc.json 服务账号/密码后启动器或冒烟测试失败 | 启动脚本与冒烟测试会自动/参数化读取 orthanc.json；确认 JSON 格式正确后**重启 Orthanc** 生效，再重试 |

| 备份提示“密码错误”但确认没输错 | 备份密码区分大小写；`verify` 用错误密码快速失败（头部 kc 指纹）；确系遗忘密码则该归档无法恢复（AES-256-GCM 无后门） |
| 网页点「开始备份」无反应 | 先看「立即备份」卡片下方进度框是否出现；F12 控制台排错；确认 admin 角色；服务器上 `tools\backup.py backup --dest local` 可离线复现 |
| 备份期间 Orthanc 状态灯变红 | 正常：备份的一致性窗口内 Orthanc 被短暂优雅停止（数秒~数十秒）后自动拉回，无需人工干预 |
| 异机目的地（UNC/NFS）写入失败 | 确认路径可写（服务账号权限）；`tools\backup.py list --dest offsite` 排错；目的地未启用时网页会提示先启用 |
| 恢复后 OHIF 阅片空白 | 检查恢复日志中 index 快照模式；跑冒烟测试；确认恢复时两个服务均已停止（否则索引与存储可能撕裂） |
